# AI 室內改造 SaaS 共識文件

## 1. 已確認決策

1. 產品定位：作為現有 `Fit Renov` repo 內的「新產品線」規劃，不直接覆寫既有引流網站定位。
2. MVP 輸入方式：首版支援 `照片上傳 + 戶型圖上傳`。
3. MVP 輸出目標：以 `2D AI 風格效果圖` 為核心交付。
4. 商業模式：採 `免費體驗 + 點數制`。
5. 技術棧：優先採 `PHP + CodeIgniter 4`，不再以 `Next.js` 作為必要前提。

## 2. 產品目標

打造一個讓使用者能快速上傳室內照片或戶型圖，選擇空間類型與裝修風格，並在短時間內獲得多版本 2D 裝修提案圖的 Web SaaS 平台。

## 3. MVP 驗收標準

### 3.1 使用者價值驗收

- 使用者可建立帳號並建立個人空間專案。
- 使用者可上傳至少一種輸入素材：
  - 室內照片
  - 戶型圖
- 使用者可為專案指定：
  - 房間類型
  - 裝修風格
  - 額外偏好條件（例如色調、材質、收納感）
- 系統可產出至少 1 組可瀏覽的 2D 風格效果圖。
- 使用者可對不同輸出版本進行查看、比較與重新生成。

### 3.2 商業驗收

- 新訪客可清楚理解產品價值與操作流程。
- 免費用戶可完成有限次體驗。
- 點數機制可支援：
  - 體驗次數扣點
  - 加購點數
  - 查詢剩餘額度

### 3.3 技術驗收

- 前端頁面支援桌面與手機版基本可用。
- 上傳流程具備格式、大小與錯誤處理。
- AI 任務有明確狀態：
  - 待處理
  - 生成中
  - 成功
  - 失敗
- AI 提供者與風格模板可替換，不把供應商邏輯硬寫進畫面層。

## 4. 任務邊界

### 4.1 納入範圍

- SaaS 官網與登入入口
- 使用者 Dashboard
- 專案建立與素材上傳
- 風格模板選擇
- AI 改造任務建立與結果展示
- 免費額度與點數邏輯
- 基本後台管理能力

### 4.2 排除範圍

- 原生 LiDAR 掃描 SDK 開發
- 自建 3D 掃描或幾何重建引擎
- 高精度可編輯 3D 建模
- 設計圖施工報價、工料清單自動估算
- 原生 iOS / Android App
- 複雜團隊協作權限與企業組織架構

## 5. 產品原則

1. 輕量級：MVP 只做「上傳 -> 選風格 -> 生成 -> 觀看結果 -> 消耗點數」的主路徑。
2. 低耦合：輸入來源、AI 提供者、支付系統必須可替換。
3. 易替換：用 adapter / provider 方式封裝第三方整合。
4. 易刪除：實驗性功能如比較視圖、提示詞增強器，需做獨立模組。
5. 安全底線：API Key、Webhook Secret、儲存憑證一律走 `.env`。

## 6. 技術約束

### 6.1 基礎棧

- 採 `PHP + CodeIgniter 4` 作為主要 Web 應用框架。
- 優先以單體式 MVC 架構完成 MVP，不在初期拆分微服務。
- 前端以伺服器渲染頁面為主，必要互動再局部加入輕量 JavaScript。
- 優先採成熟外部服務縮短上市時間。

### 6.2 建議基礎設施

- Auth：優先評估 `CodeIgniter Shield` 或等效認證方案
- DB：優先使用 `MySQL` 或 `PostgreSQL`
- Storage：物件儲存或本地儲存抽象層
- Payment：優先評估 `Stripe`
- AI Generation：使用可商用的第三方影像生成或編輯 API
- 背景任務：以資料表佇列 + CLI command + cron 方式處理生成流程

### 6.3 輸入處理原則

- `照片上傳` 是首要流程，直接支援 jpg / png / webp。
- `戶型圖上傳` 第一版以圖片或 PDF 轉圖片流程為主，不承諾 CAD 精確解析。
- 若未來接第三方掃描資料，需透過獨立 import adapter 處理，不污染現有任務模型。
- Controller 只負責請求協調，檔案驗證、任務建立、扣點邏輯應放在 service 層。

## 7. 核心資料概念

- User：帳號與方案資訊
- Project：空間專案
- Asset：照片、戶型圖與輸入素材
- StylePreset：風格模板
- GenerationJob：AI 生成任務
- GenerationResult：輸出結果
- CreditLedger：點數帳本

## 8. 風險與對策

1. 生成品質不穩定
   - 對策：先建立固定風格模板與 prompt 策略，不開放過度自由輸入。
2. 成本失控
   - 對策：免費版限次，高清輸出與重生成消耗點數。
3. 使用者期待落差
   - 對策：官網明確標示「概念提案圖」，不是施工圖或最終精裝效果保證。
4. 現有品牌干擾
   - 對策：新產品線採獨立資訊架構與導航入口。

## 9. 成功指標

- 首次生成完成率
- 免費用戶轉付費率
- 單次生成平均成本
